이 로드맵의 기간은 학습 계획의 예시다. 하루에 읽을 분량보다 실행 결과를 설명할 수 있는지를 완료 기준으로 삼는다. 기존 경험과 실습 시간에 맞춰 늘리거나 줄인다.

## 처음부터 완주하는 경로

| 단계 | 읽을 장 | 직접 남길 결과물 | 완료 기준 |
|---|---|---|---|
| API 계약 | 1~4 | 문서 CRUD와 요청·응답 모델 | 잘못된 입력·누락·null·없는 ID의 결과 설명 |
| 실행 모델 | 5~8 | ASGI 타임라인과 동시성 실험 | 블로킹·스레드·취소·자원 정리 구분 |
| 데이터 설계 | 9~12 | 계층 구조·트랜잭션·캐시 정책 | 세션 소유자·연결 예산·무효화 실패 설명 |
| 보안 경계 | 13~15 | 인증·객체 권한·오류 계약 | 다른 사용자 데이터 접근 거절 검증 |
| 연동과 테스트 | 16~19 | timeout·SSE·작업·통합 테스트 | 외부 실패·취소·중복 실행 재현 |
| 운영 | 20~24 | 부하 시나리오·대시보드·장애 기록 | 느려진 구간과 포화 자원을 지표로 설명 |
| AI 서비스 | 25~30 | 로컬 통합판과 운영 확장 설계 | 근거·사용자 격리·비용·복구 정책 설명 |

## 핵심 8개 장

- [ ] [5장 ASGI](../05-asgi-uvicorn/chapter.md): TCP 연결과 HTTP 요청의 수명을 구분하고 send 이벤트를 설명한다.
- [ ] [6장 asyncio](../06-asyncio-event-loop/chapter.md): 코루틴·Task·Future와 gather·TaskGroup의 실패 차이를 설명한다.
- [ ] [7장 동시성](../07-concurrency/chapter.md): 직접 호출한 동기 helper의 실행 위치와 워커별 한도를 설명한다.
- [ ] [8장 의존성](../08-dependencies-middleware/chapter.md): 캐시 범위·yield 정리·미들웨어 문맥을 설명한다.
- [ ] [11장 비동기 DB](../11-async-database/chapter.md): Task별 세션과 트랜잭션·연결 풀의 수명을 구분한다.
- [ ] [17장 스트리밍](../17-streaming/chapter.md): 응답 시작 후 오류·disconnect·느린 소비자 정책을 설명한다.
- [ ] [20장 측정](../20-performance-measurement/chapter.md): 유효 처리량·오류율·p95와 부하 모델을 함께 해석한다.
- [ ] [24장 장애](../24-incidents-concurrency/chapter.md): 취소·deadline·풀 고갈·공유 상태를 재현하고 복구를 설명한다.

체크는 읽었다는 뜻이 아니라 실행 결과와 실패 결과를 설명했다는 뜻이다. 각 장의 확인 문제에 자신의 문장으로 답하고 해설과 비교하자.

## 기존 백엔드 개발자를 위한 빠른 경로

Spring Boot 경험자는 4장에서 데이터 계약을 확인한 뒤 5~8장의 실행 모델을 읽고 11장의 세션·트랜잭션을 연결한다. familiar한 Controller·Service·Repository 이름을 옮기기 전에 자원 수명과 예외 전달을 옮긴다.

Express.js 경험자는 6장의 코루틴 시작 시점과 7장의 직접 동기 호출을 먼저 확인한다. JavaScript Promise 예약 순서를 Python에 그대로 기대하지 않는다. Python 라이브러리가 비동기 드라이버를 제공하는지도 확인한다.

AI 프로젝트 경험자는 25장으로 바로 들어가기 전에 11·17·18·24장을 읽는다. 모델 호출만 성공하는 데모에서 작업 복구와 비용 제어가 가능한 서비스로 넘어가는 경계를 배우기 위해서다.

## 설계 리뷰용 질문

Knowledge Hub의 각 경로에 대해 다음 질문에 답하는 문서를 한 페이지 작성하자.

1. 누가 호출할 수 있고 어느 객체를 볼 수 있는가?
2. 입력 크기와 출력 크기의 한도는 무엇인가?
3. 어떤 자원을 점유하며 얼마나 오래 점유하는가?
4. 동시에 몇 개를 실행하고 대기는 몇 개까지 허용하는가?
5. 언제 timeout·취소·거절이 발생하는가?
6. 요청을 두 번 보내면 어떤 부수효과가 생기는가?
7. 응답 전과 응답 후 실패를 어떻게 구분하는가?
8. 프로세스를 재시작하면 무엇이 남고 무엇이 사라지는가?

답변이 코드에 반영되어 있고 테스트나 지표로 확인된다면 설계 리뷰가 실행 가능한 검토가 된다.
