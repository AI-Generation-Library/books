# 16장. 도입 방식 선택하기

직접 개발과 외부 서비스 도입은 단순한 가격 비교가 아니다. 업무에 필요한 통제, 운영 역량, 데이터 처리 조건과 변경 가능성을 함께 비교한다. 같은 조직에서도 일반 문서 작성과 핵심 업무 자동화에는 다른 방식을 선택할 수 있다.

## 1. 요구사항을 먼저 고정하기

모델이나 공급사 이름을 고르기 전에 대상 업무, 자료 민감도, 사용자 수, 지연 요구, 권한과 승인, 로그와 삭제 조건을 정한다. 반드시 충족할 조건과 협상 가능한 조건을 구분한다. 조건을 만족하지 못하는 후보를 성능 점수로 보완하지 않는다.

AI 제공자가 처리하는 데이터의 저장 위치, 보관·학습 사용 여부, 삭제 절차와 장애 지원은 제품·계약·설정에 따라 달라질 수 있다. 과거에 확인한 정보나 홍보 문구만으로 현재 조건을 확정하지 않는다. 실제 도입 시 공식 문서와 계약을 다시 확인하고 확인 날짜를 남긴다.

## 2. 네 가지 경로를 비교하기

| 경로 | 적합할 수 있는 상황 | 추가 확인 |
| --- | --- | --- |
| 완성형 업무 서비스 | 표준 업무, 빠른 적용 | 권한·전송·삭제·내보내기 |
| 기존 시스템의 AI 기능 | 기존 흐름과 사용자 기반 활용 | 기존 권한의 실제 적용 범위 |
| 모델 API와 자체 앱 | 특화 업무·통제·화면 필요 | 개발·평가·보안·운영 인력 |
| 자체 운영 모델 | 배포 통제와 내부 환경 필요 | 하드웨어·모델 권리·업데이트·품질 |

자체 운영은 데이터가 외부로 나가지 않는 구성에 도움이 될 수 있지만 자동으로 안전하거나 저렴한 것은 아니다. 취약점, 권한, 백업, 공급망과 운영 인력은 여전히 필요하다. 외부 서비스를 쓰더라도 업무 경계와 책임을 공급사에 모두 넘길 수는 없다.

## 3. 공통 평가 조건으로 비교하기

후보마다 다른 질문을 넣고 좋은 결과만 고르면 비교가 왜곡된다. 같은 자료·질문·평가 기준·권한·시간 제약을 사용한다. 실제 비용은 입력과 출력, 검색, 저장, 재시도와 운영 비용을 포함한다. 이 책은 특정 모델의 현재 가격이나 순위를 고정하지 않는다.

평가에는 정상 사례뿐 아니라 자료 부족, 권한 변경, 장애와 삭제 요청을 넣는다. 문서상 지원 기능과 실제 설정·동작을 구분한다. 공급사가 답한 기능은 증거 문서나 제한된 테스트로 확인한다.

품질과 비용의 차이가 작다면 유지보수나 도입 속도가 결정 요인이 될 수 있다. 반대로 필수 통제에 차이가 있다면 전체 평균 품질이 더 높더라도 후보를 보류한다.

## 4. 교체와 철수 비용을 계산하기

지시, 평가 세트, 문서 메타데이터와 업무 규칙을 가능한 한 제품 내부 설정에만 가두지 않는다. 내보낼 수 있는 데이터 형식, 삭제 확인, 계약 종료 시 접근, 대체 시스템의 준비 기간을 확인한다.

모델 교체는 주소만 바꾸는 작업이 아니다. 출력 형식, 보류 행동, 지연과 실패가 달라질 수 있다. 동일 평가 세트와 운영 조건에서 다시 확인하고 단계적으로 전환한다. 전환 전후 버전을 기록해 성능 변화의 원인을 추적한다.

## 5. 솔빛서비스의 선택 문서

솔빛서비스는 첫 파일럿에서 읽기 중심 검색과 초안, 내부 화면과 사람 검토가 필요하다. 완성형 서비스가 이 조건을 충족하면 빠른 실험을 선택할 수 있다. 고객별 문서 권한과 근거 확인을 구현해야 한다면 자체 앱 경로가 후보가 된다.

선택 문서에는 후보, 필수 조건의 증거, 평가 결과, 총비용 가정, 책임자와 보류 요인을 기록한다. “유명해서 선택”보다 현재 업무와 제약에 맞는 이유를 설명한다. 미래의 모든 업무까지 미리 해결하려는 플랫폼 구축은 파일럿 범위를 키울 수 있다.
