# 14장. 개발과 지식 업무의 AX

개발자는 코드를, 기획자는 보고서를, 분석가는 해석을 빠르게 만들 수 있다. 그러나 산출물의 생산 속도가 검증 속도를 넘으면 오류가 더 많이 퍼진다. 지식 업무의 AX에서는 생성량보다 검증 가능한 결과와 팀의 이해를 중심에 둔다.

## 1. 제안과 근거를 분리하기

AI가 제안한 코드나 설명은 검토 대상이다. 코드는 요구사항과 실행 결과로, 보고서는 원자료와 추론으로 검증한다. 존재하지 않는 함수나 문헌을 그럴듯하게 제시할 수 있으므로 이름만 믿지 않고 공식 문서나 실제 파일을 확인한다.

보고서에서는 관측 사실, 계산, 해석과 제안을 구분한다. “매출이 감소했다”는 원자료와 계산이 필요하고 “기능 변경이 원인이다”는 추가 근거가 필요하다. AI가 만든 설득력 있는 이야기가 인과관계를 증명하지 않는다.

## 2. 개발 작업의 경계를 정하기

작은 변경은 요구사항, 변경 가능한 파일, 기존 동작, 완료 조건을 명시한다. AI에게 저장소 전체를 임의로 고치게 하기보다 필요한 맥락을 제공한다. 테스트 결과뿐 아니라 변경 차이도 검토한다. 테스트가 통과해도 비밀 노출이나 불필요한 의존성 추가가 있을 수 있다.

```text
작업: 문의 분류 결과의 허용 값 검증을 추가한다.
입력: 기존 API 계약과 분류 결과 샘플.
범위: 검증 모듈과 관련 테스트.
유지 조건: 기존 정상 요청의 응답 형식 유지.
완료: 알 수 없는 유형은 인계 대상으로 처리하고 이유를 기록.
검증: 정상 유형, 누락, 잘못된 유형과 과도한 길이 사례 확인.
```

실행 환경에는 개발용 권한만 제공한다. 실제 운영 비밀이나 고객 데이터를 프롬프트와 로그에 넣지 않는다. 코드 실행, 패키지 설치와 배포는 각각 영향이 다르므로 도구 권한을 분리한다. 자동 생성된 변경을 운영에 적용할 때에는 기존 배포·검토 절차를 거친다.

## 3. 테스트가 확인하는 범위를 설명하기

AI가 구현과 같은 논리로 테스트를 만들면 같은 오류를 함께 반복할 수 있다. 요구사항에서 기대 결과를 도출하고 경계값, 실패와 권한 사례를 포함한다. 도메인 전문가가 알고 있는 예외도 중요하다.

이 책의 비용 계산 예제는 API 없이 실행되는 작은 도구다. 테스트는 계산식과 입력 검증을 확인한다. 실제 기업의 시간 절감이나 투자 성과를 확인하지 않는다. 작은 도구에서도 검증 범위를 이렇게 명확히 적는 습관이 필요하다.

| 산출물 | 확인할 증거 | 확인하지 못하는 것 |
| --- | --- | --- |
| 코드 | 테스트·변경 검토·실행 로그 | 모든 운영 환경의 안전 |
| 요약 | 원문과 중요 정보의 대응 | 원문의 사실 자체가 참인지 |
| 분석 | 데이터 정의·계산 재현 | 관찰만으로 인과관계 확정 |
| 기획안 | 가정·대안·실행 조건 | 미래 성과 보장 |

## 4. 회의와 문서 업무를 재설계하기

회의 요약은 발언과 결정, 담당자와 기한을 나눠 작성한다. 논의 후보를 확정된 결정으로 바꾸지 않고, 참석자에게 확인할 경로를 둔다. 녹음·전사와 외부 전송은 동의, 정책과 개인정보 요건을 확인한다.

기획 문서에는 사용한 자료의 출처와 날짜를 남긴다. 외부 정보는 실제로 확인한 링크와 확인 범위를 기록한다. 존재하지 않는 출처를 AI가 만들어 넣지 않도록 목록을 검증한다. 최신 정보가 필요한 주제라면 모델의 기존 지식만으로 완료 처리하지 않는다.

## 5. 팀의 이해를 남기기

AI가 코드를 만들었더라도 팀은 운영할 수 있어야 한다. 변경 이유, 데이터 흐름, 장애 시 행동과 소유자를 문서에 남긴다. 문서가 너무 길어지면 핵심 설계 결정과 실행 절차를 분리한다.

솔빛서비스는 검색 결과의 문서 ID를 검증하는 작은 기능부터 개발 지원을 적용할 수 있다. 고객 답변 파일럿과 개발 지원은 서로 다른 평가 과제다. 코드가 통과했다고 답변 품질을 검증한 것으로 보고하지 않는다.

## 실습: AI 산출물의 검증 계약

코드 변경이나 분석 보고서 하나를 골라 입력, 산출물, 금지 변경, 완료 조건을 적는다. 생성 전에 독립된 검증 사례 세 개를 만든다. 이후 결과를 보며 실패를 찾아 수정하고, 확인하지 않은 범위를 한 문단으로 남긴다. [실습 자료 안내](../examples/README.md)의 계산 예제를 사용해도 된다.
