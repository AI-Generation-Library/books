# 05장. AX 준비도 진단

파일럿을 시작하려고 하자 서로 다른 의견이 나온다. 현업은 자료가 있다고 말하고 개발팀은 사용할 수 있는 형태인지 묻는다. 보안 담당자는 자료를 어디로 보내는지 확인해야 한다고 말한다. 이때 “준비가 되었는가”라는 하나의 질문보다 무엇을 근거로 어떤 범위를 시작할 수 있는지 확인해야 한다.

## 1. 진단의 목적은 실행 순서 정하기

준비도 진단은 조직의 우열을 평가하거나 모든 항목을 최고 수준으로 만드는 작업이 아니다. 선택한 업무를 검증하기 위해 필요한 조건과 선행 작업을 찾는 과정이다. 업무마다 준비 상태가 다르므로 조직 전체의 평균 점수만으로 파일럿을 정하지 않는다.

한 부서의 공개 문서를 요약하는 업무와 여러 부서의 고객 데이터를 연결하는 업무는 필요한 조건이 다르다. 작은 범위에서 필요한 조건을 확인하고, 그 범위를 넘어서는 데이터나 권한은 다음 단계의 검토 대상으로 남길 수 있다. 진단의 결과가 “현재는 시작하지 않는다”일 수도 있다.

## 2. 네 영역을 증거로 점검하기

| 영역 | 확인할 질문 | 증거의 예 |
| --- | --- | --- |
| 업무 | 입력·완료·예외·승인 단계가 명확한가 | 업무 흐름, 사례, 담당자 인터뷰 |
| 데이터 | 자료의 소유자·유효성·이용 권한을 아는가 | 문서 목록, 버전, 공개 등급 |
| 인력 | 검토·운영·지원 책임과 시간이 있는가 | 역할표, 교육 계획, 운영 시간 |
| 시스템 | 접근·연결·기록·복구가 가능한가 | 권한표, 연동 명세, 장애 절차 |

“대체로 잘 되어 있다”는 답변은 증거가 아니다. 문서를 열어 실제 버전과 소유자를 확인하고, 업무 담당자가 예외 사례를 어떻게 처리하는지 관찰한다. 시스템 연결이 가능하다고 말하면 테스트 환경, 사용할 API와 승인 절차를 확인한다.

증거가 없다는 사실도 기록한다. 아직 측정하지 않았고, 담당자는 있지만 결정되지 않았으며, 자료는 있지만 이용 권한이 불명확하다는 상태를 구분한다. 모두를 “미흡”이라고 표시하면 다음 행동이 모호해진다.

## 3. 점수보다 중요한 필수 조건

진단표에 점수를 넣으면 비교가 쉬워지지만 평균이 치명적인 문제를 가릴 수 있다. 데이터 품질과 사용자 만족이 높아도 자료를 해당 용도로 사용할 권한이 없다면 그 자료를 사용하는 파일럿을 시작할 근거가 되지 않는다. 책임자가 없거나 중단할 방법이 없는 것도 먼저 해결해야 할 조건이다.

이 책의 진단표는 점수와 필수 조건을 분리한다. 점수는 개선 우선순위를 논의하는 보조 자료이며, 필수 조건은 해당 범위의 진행 여부를 판단하는 질문이다. 필수 조건의 구체적인 내용은 업무의 위험과 조직 정책에 맞게 정한다.

예를 들어 고객에게 직접 발송하는 업무는 공개 책임과 승인 절차를 확인해야 한다. 초안만 만드는 내부 실험도 자료 이용 범위와 검토자를 정해야 한다. 위험이 높은 업무를 낮은 위험 실험의 점수표로 평가하지 않는다.

## 4. 가상 사례: 자료는 있지만 책임이 없는 상태

솔빛서비스에는 고객지원 문서가 여러 폴더에 있다. 자료의 양은 충분해 보이지만 최신 문서가 무엇인지 팀마다 다르게 알고 있다. 내부 문서와 고객에게 안내할 수 있는 문서도 섞여 있다. AI가 검색할 수 있다는 기술적 사실만으로 업무 적용을 시작하면 공개 범위와 버전 문제가 남는다.

팀은 먼저 파일럿에 사용할 문서를 제한한다. 각 문서에 소유자, 버전, 유효 기간과 공개 등급을 기록한다. 충돌하거나 소유자가 없는 자료는 제외하고, 그 자료가 필요한 문의는 기존 담당자에게 인계한다. 이 작업은 파일럿을 작게 만들지만 실패 원인을 확인하기 쉽게 한다.

운영 책임도 정한다. 자료 갱신은 현업 문서 소유자, 접근 권한과 연결은 시스템 담당자, 초안의 외부 공개는 고객지원 업무 책임자가 맡는다. 같은 사람이 여러 역할을 맡더라도 책임 항목과 필요한 시간을 명시한다.

## 5. 진단 결과를 행동으로 바꾸기

각 항목에는 상태, 근거, 선행 작업, 책임자와 완료 확인 방법을 적는다. “데이터 정비 필요”처럼 큰 표현을 “파일럿 문서 5종의 최신 버전과 공개 등급 확인”처럼 완료 여부를 확인할 수 있는 작업으로 바꾼다.

| 상태 | 다음 행동 |
| --- | --- |
| 확인 완료 | 확인한 범위와 날짜를 기록하고 사용 |
| 부분 확인 | 사용 가능한 범위를 제한하고 남은 작업 지정 |
| 미확인 | 증거를 확보하기 전 해당 범위 보류 |
| 사용 불가 | 대체 자료·업무·도입 방식을 검토 |

진단 결과에는 유효 기간이 있다. 문서, 계약, 시스템과 담당자가 바뀌면 다시 확인해야 한다. 파일럿 시작 시점의 진단을 전사 확산의 근거로 계속 재사용하지 않는다.

## 직접 해 보기

```text

책임자와 완료 확인 방법:
그동안 사용할 제한된 범위:
```

## 점검 질문과 정리

- 평균 점수가 필수 조건의 미충족을 가리고 있지 않은가?
- 자료의 양과 이용 가능성을 구분하는가?
- 선행 작업의 책임과 완료 기준이 명확한가?

준비도 진단의 좋은 결과는 높은 점수보다 실행 가능한 다음 작업이다. 다음 장에서는 이 조건을 바탕으로 어떤 문제를 먼저 해결할지 구체화한다.
