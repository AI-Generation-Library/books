# 29장. 통합 실습: 가상 기업의 AX 프로젝트

이 장에서는 솔빛서비스의 고객 지원 과제를 실행 가능한 파일럿 묶음으로 정리한다. 회사, 문서, 물량과 비용은 모두 학습용 가정이다. 실제 고객 데이터나 API 키 없이 설계를 검토하고 계산 예제를 실행할 수 있다. 여기서 만든 평가 계획을 실제 모델 성능이나 기업 성과로 발표하지 않는다.

## 1. 문제와 범위를 고정하기

가상 문제는 담당자가 현재 정책과 제품 안내를 찾는 데 시간이 들고, 자료 부족이나 공개 범위를 확인하려고 재작업하는 것이다. 월 문의 2,400건과 건당 10분은 계획을 설명하는 가정이며 관측된 기준선이 아니다. 파일럿을 시작하면 실제 대상과 기준선을 수집해야 한다.

목표는 승인 자료 검색과 답변 초안이 업무 부담을 줄이면서 근거·공개 범위·인계를 유지하는지 확인하는 것이다. 외부 발송과 계약 예외 승인, 환불·계정 변경은 범위 밖이다. 초안은 사람이 검토하고 기존 화면에서 발송한다.

산출물은 문제 정의서, 과제 평가표, 파일럿 기획서와 비용·효과 표다. [워크시트 모음](../appendices/workbook.md)을 사용해 각 문서의 가정과 미확인을 표시한다.

## 2. 자료를 등록하고 검색 경계를 정하기

[실습 자료](../examples/README.md)의 다섯 문서를 데이터 등록부에 옮긴다. DOC-FAQ는 공개 일반 안내, DOC-SUPPORT는 공개 지원 정책, DOC-RELEASE-OLD는 과거 자료, DOC-SECURITY는 내부 자료, DOC-CONTRACT는 제한 자료다.

고객 답변 초안 경로에는 현재 승인된 공개 자료만 제공한다. 담당자가 내부 자료를 읽을 수 있더라도 외부 답변의 근거 범위는 별도로 제한한다. 과거 자료는 이력 질의 목적과 명확한 표시가 있을 때만 검토한다.

문서 ID·버전·현재성·읽기 범위와 공개 등급을 정리한다. 충돌이나 누락이 발견되면 문서 소유자에게 수정 작업을 배정한다. 이 단계가 끝나지 않았다면 모델에 더 많은 자료를 넣는 것으로 문제를 덮지 않는다.

## 3. 업무와 도구 계약을 작성하기

접수에서 제품 버전과 문의 유형을 확인하고, 사용자 권한에 맞는 자료를 검색한다. 충분한 근거가 있으면 초안과 근거를 보여주고, 없으면 추가 질문 또는 담당자 인계로 전환한다. 검토자는 사실, 현재성, 공개 범위와 다음 행동을 확인한다.

첫 도구는 자료 검색과 내부 초안 저장으로 제한한다. 각 도구의 입력 스키마, 허용 대상, 시간 제한과 실패 처리, 요청 ID를 적는다. 외부 발송 도구를 제공하지 않는다. 사람의 최종 발송은 기존 업무 흐름에 남긴다.

## 4. 24개 사례를 평가 계획으로 사용하기

평가 파일에는 다음 구성이 들어 있다. 기대 행동은 저자가 제안한 학습용 기준이며 실제 운영의 정답으로 자동 적용하지 않는다.

| 유형 | 개수 | 확인할 경계 |
| --- | --- | --- |
| 일반 문의 | 8 | 공개 자료와 정확한 주장 |
| 부족·충돌 | 6 | 질문·인계·과거 정책 구분 |
| 권한 | 6 | 조직·공개 범위·제한 자료 |
| 악성 요청 | 4 | 비밀·외부 전송·실행 지시 차단 |

각 사례의 기대 행동, 허용 근거와 금지할 주장을 검토한다. 자동 검사로 ID 중복, 문서 참조와 분류 개수를 확인할 수 있다. 이는 데이터 구조 검사다. 모델을 실행하지 않았으므로 답변 정확도나 안전성 점수는 산출하지 않는다.

실제 API 실험을 한다면 승인된 제공자·모델·키와 비용 한도, 처리 조건을 먼저 확인한다. 키는 공개 파일이나 채팅에 넣지 않는다. 결과에는 실행 환경과 각 사례의 통과·실패·보류, 사용 비용과 미확인을 기록한다.

## 5. 계산 예제를 실행하기

로컬에서 ZIP을 풀고 `examples` 폴더로 이동한다. Python 3.10 이상과 표준 라이브러리만 사용하는 예제이며 AI API는 호출하지 않는다.

```powershell
python roi_calculator.py baseline-assumptions.json
python -m unittest discover -s . -p "test_*.py" -v
```

기본 가정의 산술 결과는 유효 적용 1,440건, 월 시간 변화 96시간, 잠재 시간 가치 240만원이다. 월 경제적 부담 190만원을 빼면 차이는 50만원이다. 현금화 비율 0.25를 가정한 월 현금 변화는 -30만원이며 양의 단순 회수 기간은 없다.

이 결과는 입력한 가정의 계산이다. API 가격이나 기업의 실제 효과를 검증하지 않는다. 가정 파일에서 적용률과 처리 후 시간을 바꿔 민감도를 확인한다. 처리 후 시간이 더 길어지면 음수 시간 변화가 나오는 것이 정상이며 이를 0으로 숨기지 않는다.

## 6. 모의 사건과 확대 결정을 수행하기

다른 고객 자료가 초안에 포함된 사건을 가정한다. 관련 경로를 중단하고 기존 흐름으로 복귀한 뒤 자료·권한·캐시와 노출 범위를 확인한다. 수정과 필요한 평가를 수행하고 재개 승인자를 정한다.

최종 검토에서는 유지, 개선 후 재검토, 중단이나 제한적 확대 중 하나를 선택한다. 설계와 계산만 완료한 현재 단계에서는 실험 준비 상태를 검토할 수 있을 뿐 운영 확대를 승인할 실적은 없다. 필요한 다음 증거를 명확히 적는다.

## 실습 완료 기준

범위·책임·자료·권한·평가·비용·대체 흐름이 서로 일치해야 한다. 예를 들어 기획서가 공개 자료만 쓴다고 하면서 검색 계약이 내부 전체 자료를 제공한다면 수정한다. 워크시트의 빈칸을 모두 채웠다는 사실보다 문서 간 모순을 찾는 것이 중요하다.

2. 파일럿 범위와 도구·권한 계약이 일치하는가?
3. 지금 확대를 판단하기 위해 아직 필요한 증거는 무엇인가?
