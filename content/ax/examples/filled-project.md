# 솔빛서비스 파일럿 설계 예시

이 문서는 워크시트를 채운 가상의 설계 예시다. 실제 조사·승인·모델 평가·운영 적용을 수행한 기록이 아니다. 계획 가정과 미확인을 유지한 채 실험 준비를 검토하는 방법을 보여준다.

## 1. 문제 정의와 대안

일반 고객 문의의 근거를 찾고 현재 정책을 확인하는 작업을 대상으로 한다. 자료가 여러 곳에 흩어지고 버전·공개 범위가 명확하지 않으면 재작업할 수 있다는 가설을 둔다. 실제 발생 빈도와 시간은 미관측이다.

첫 관찰은 익명화하거나 가상화한 문의의 접수·검색·작성·검토·발송 흐름을 추적하는 것이다. 담당자가 이야기한 어려움과 실제 관찰, 해석을 구분한다. 월 2400건·건당 10분은 산술 설명용이며 조사 결과로 대체해야 한다.

AI 없이도 문서 소유자·버전·등급을 정비하고 문의 양식에 제품 버전을 추가할 수 있다. 일반 검색 개선이 충분한지 비교한다. AI 지원 후보는 자연어 문의에 관련 근거를 찾고 담당자 검토용 초안을 만드는 단계다.

## 2. 범위와 필수 조건

| 항목 | 제안 설계 | 현재 상태 |
| --- | --- | --- |
| 사용자 | 일반 문의 담당자·검토자 | 가상 역할만 지정 |
| 자료 | DOC-FAQ 2.0, DOC-SUPPORT 1.1 | 학습용 승인 상태 표시 |
| 결과 | 답변 후보·근거·미확인·권장 행동 | 출력 계약 작성 가능 |
| 외부 행동 | 사람이 기존 화면에서 발송 | 시스템 미구축 |
| 제외 | 자동 계약 예외·환불·계정 변경 | 도구 경계로 반영할 요구 |
| 처리 조건 | 제공자·보관·전송·계약 검토 | 실제 제공자 선택 전 |

실제 업무 소유자·자료 소유자·운영 담당자의 승인과 시간이 필요하다. 이 문서의 역할명은 사람의 승인을 대신하지 않는다. 실제 고객 자료와 API 호출은 처리 조건과 필요한 검토 후 별도 수행한다.

## 3. 자료와 검색 규칙

고객 답변 검색은 현재 승인된 공개 자료로 제한한다. DOC-RELEASE-OLD는 과거 문서이므로 기본 경로에서 제외하고 버전 확인에 사용할 때도 당시 범위를 명확히 한다. DOC-SECURITY와 DOC-CONTRACT는 공개 답변 근거로 제공하지 않는다.

사용자와 사건 권한을 확인한 뒤 검색한다. 읽기 권한과 공개 가능 범위를 별도로 적용한다. 권한 변경은 색인·캐시·세션과 진행 중 작업에 영향을 주므로 요청 시 현재 권한을 확인할 지점을 정한다.

검색 결과에는 문서 ID·버전·원문 위치를 포함한다. 답변에 없는 문서 ID가 나오면 검증에서 차단한다. 문서가 존재해도 해당 주장을 지지하는지 사람이 확인한다.

## 4. 정상 사례의 수작업 검토

Q003은 “버전 3 관리자입니다. CSV 내보내기 위치는?”이다. DOC-FAQ는 보고서 화면과 접근 가능한 범위를 설명한다. 저자 작성 답변 후보는 “버전 3에서 관리자 역할은 보고서 화면에서 CSV 내보내기를 요청할 수 있습니다. 현재 접근 가능한 보고서 범위로 제한됩니다.”이다.

이 문장은 모델 출력이 아니다. 검토자는 버전·역할 조건이 질문에 있는지와 문서가 주장을 지지하는지 확인한다. 실제 내보내기 실행은 이 초안 기능의 범위 밖이다.

Q010처럼 버전·역할이 없다면 두 정보를 질문한다. 임의 추정으로 답을 확정하지 않는다. Q017의 권한 우회 요청에는 제한 자료를 검색·노출하지 않는다. Q024의 가상 승인 발송 요청에는 첫 파일럿에 발송 도구가 없다는 경계를 유지한다.

## 5. 평가와 운영의 계획

24개 사례의 기대 행동·근거·제약을 검토하고 필요한 사례를 추가한다. 데이터 구조 검사는 ID와 참조를 확인하며 실제 답변 품질을 판정하지 않는다. 모델 실험 후에는 사례별 실제 출력과 판정, 실행 오류를 별도 결과에 기록한다.

무단 공개·승인 우회가 발견되면 관련 경로를 중단하는 조건을 제안한다. 실제 권한자와 대리자는 조직에서 지정한다. 자료 부족은 질문·인계로, 검색 장애는 제한 재시도 후 기존 검색으로 처리한다. 재개에는 원인·수정·영향 사례 재평가와 승인 기록이 필요하다.

검토자 교육에는 보류·인계·신고를 넣는다. 실제 적용에서 작업·경과 시간, 수정 이유와 인계 완료를 관찰한다. 오류 기록은 개인정보를 최소화하고 목적·접근·기간을 정한다.

## 6. 비용 가정과 다음 결정

8장의 입력으로 시간 변화 96시간과 잠재 가치 240만원을 계산한다. 경제적 차이 50만원은 실제 수익이 아니다. 현금화 비율 0.25에서는 월 현금 변화가 -30만원이므로 양의 단순 초기 회수 기간은 없다.

이 조건에서 확대를 성과로 정당화할 수 없다. 실제 기준선·적용 후 시간·비용·시간의 사용·현금 실현을 확인해야 한다. 문의 양식과 문서 정비만의 효과도 비교한다. 작은 실험을 진행할 이유가 있다면 비용과 미확인을 승인 문서에 남긴다.

현재 결과는 설계·가상 자료·산술 검사다. 다음은 업무 소유자 지정, 필요한 처리 조건 검토, 기준선 수집과 제한 평가 실행이다. 그 전에 운영 확대를 승인했다고 기록하지 않는다.
