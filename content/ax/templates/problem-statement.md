# 문제 정의서

해결책 이름을 먼저 적기보다 관찰 가능한 업무 문제를 정의한다. 이 양식의 가상 예시는 실제 솔빛서비스 조사 결과가 아니다.

- 문제 ID / 업무 / 소유자 / 작성일:
- 영향을 받는 고객·구성원:
- 관찰 방법·기간·표본:

| 항목 | 작성 내용 | 가상 예시 |
| --- | --- | --- |
| 관찰 | 실제로 본 사건·숫자·원문 | 같은 문의의 근거를 여러 화면에서 찾음 |
| 영향 | 시간·오류·대기·경험 | 검색·확인에 시간이 든다는 가정 |
| 해석 | 가능한 원인, 아직 미확인 | 문서 현재성이 불명확할 수 있음 |
| 범위 | 문의 유형·제품·사용자 | 일반 제품 문의 담당자 |
| 기준선 | 수집할 지표와 정의 | 검색·작성·검토 시간을 분리 측정 |
| 성공 | 바뀌기를 기대하는 결과 | 근거·공개 범위를 유지하며 부담 감소 |
| 제약 | 바꿀 수 없는 조건 | 계약 예외와 외부 발송은 사람 판단 |

## 대안

1. 절차·문서 정비만으로 개선할 부분:
2. 일반 검색·규칙·화면 연결로 개선할 부분:
3. AI를 사용해야 할 이유와 추가 부담:

## 다음 관찰

- 확인할 가설:
- 가설이 틀렸다고 판단할 증거:
- 관찰·수집 담당자와 기한:
- 수집을 최소화할 개인정보·비밀:

문제 정의를 검토할 때 “AI가 필요하다”는 문장을 지우고도 문제가 설명되는지 확인한다.
