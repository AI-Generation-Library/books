# 15장. AI가 사용할 데이터 준비하기

데이터 준비는 파일을 한 폴더에 모으는 작업보다 넓다. 어떤 자료를 어떤 목적으로 사용할 수 있는지, 현재 내용인지, 누구에게 공개할 수 있는지 정해야 한다. 자료를 더 많이 넣으면 성능이 좋아질 것이라는 가정은 권한과 품질 문제를 가릴 수 있다.

## 1. 자료 목록부터 만들기

문서마다 식별자, 소유자, 출처, 버전, 적용일, 상태, 읽기 권한과 공개 등급을 기록한다. 파일 이름과 수정 시각만으로 정책의 현재성을 판단하지 않는다. 누가 수정하고 누가 승인했는지 확인할 수 있어야 한다.

솔빛서비스의 자료에는 공개 FAQ, 현재 지원 정책, 과거 릴리스 안내, 내부 보안 절차와 제한된 계약 예외가 있다. 내부 담당자가 계약 예외를 읽을 수 있다고 해서 고객에게 내용을 전달해도 되는 것은 아니다. **접근 권한과 외부 공개 가능 범위는 다른 속성**으로 관리한다.

| 속성 | 예시 | 필요한 이유 |
| --- | --- | --- |
| document_id | DOC-FAQ | 근거를 안정적으로 식별 |
| version | 2.0 | 수정 전후를 구분 |
| status | approved / archived | 기본 검색 대상 결정 |
| owner | 고객지원 문서 담당 | 오류 수정 책임 |
| read_scope | support | 내부 검색 접근 제한 |
| disclosure | public / internal / restricted | 출력·전달 범위 결정 |
| effective_from | 시행일 | 질문 시점과 정책 연결 |

실제 구현에서는 속성 값과 권한 집행 규칙을 조직에 맞게 정의한다. 이 표의 명칭이 표준이나 인증 요구사항은 아니다.

## 2. 품질을 사용 목적에 맞춰 확인하기

PDF의 표가 줄글로 깨졌다면 금액과 조건이 잘못 연결될 수 있다. 스캔 문서의 문자 인식 오류, 중복 페이지, 빠진 각주와 잘못된 링크를 점검한다. 길이가 짧아졌다는 이유로 좋은 요약이라고 보지 않는다.

업무 질문을 기준으로 샘플을 고른다. 제품 버전별 안내, 예외 조항, 금지 사항처럼 오류 영향이 큰 부분을 먼저 확인한다. 원문과 추출본이 연결되어야 담당자가 내용을 비교하고 수정할 수 있다.

충돌은 정제만으로 해결되지 않는다. 두 정책이 다르면 소유자가 우선순위를 정하고 하나를 폐기하거나 적용 대상을 명확히 해야 한다. AI에게 충돌을 알아서 해결하게 맡기지 않는다.

## 3. 최소한의 자료를 선택하기

개인정보를 제거하거나 가명 처리했다고 모든 사용 위험이 사라지는 것은 아니다. 다른 자료와 결합해 개인을 식별할 수 있는지, 사용 목적과 보관 기간이 적절한지 검토한다. 실제 법적 근거와 전송 조건은 22장에서 별도로 다룬다.

학습, 검색, 평가, 운영 로그는 서로 다른 목적이다. 운영 데이터를 수집했다는 이유만으로 모델 학습이나 테스트 세트 재배포에 사용하지 않는다. 외부 제공자의 처리·보관 조건과 조직의 계약·정책도 확인한다.

이 책의 예제는 처음부터 가상 자료로 만든다. 실습의 목적은 권한과 평가 설계를 배우는 것이므로 실제 고객 데이터가 필요하지 않다.

## 4. 변경과 삭제의 경로를 설계하기

문서를 삭제해도 검색 색인, 캐시, 대화 기록에 내용이 남을 수 있다. 원문에서 파생 저장소까지 연결해 변경·삭제를 전파한다. 권한 변경은 재색인 주기만 기다리지 않고 요청 시점에도 확인하는 방식이 필요할 수 있다.

변경 이력에는 문서 버전, 색인 버전과 승인 상태를 남긴다. 모델의 답변에 사용한 자료 버전을 추적하면 오류 재현과 재검증이 쉬워진다. 다만 모든 원문과 대화를 영구 보관하는 것은 피하고 필요한 범위와 기간을 정한다.

## 5. 데이터 완료 조건을 합의하기

“자료 업로드 완료”보다 소유자 지정, 권한 확인, 현재성 점검, 중요 내용 추출 검증과 삭제 경로 확인을 완료 조건으로 삼는다. 모든 문서를 완벽하게 만들 때까지 기다리기보다 승인된 작은 자료 집합에서 시작한다.

솔빛서비스는 공개 FAQ와 현재 지원 정책을 먼저 등록하고 계약 예외와 내부 보안 문서는 일반 고객 답변 경로에서 제외한다. 제외 자료도 위험 평가에서는 사용해 시스템이 누설하지 않는지 확인할 수 있다. 평가 환경에서도 접근 범위를 통제해야 한다.
