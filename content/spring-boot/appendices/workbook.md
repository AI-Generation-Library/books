아래 표는 자신의 서비스에 답을 채우는 워크북이다. “예”만 표시하지 말고 코드 위치·테스트·지표를 근거로 적는다.

## 객체와 요청

| 질문 | 기록할 근거 |
| --- | --- |
| 필수 의존성이 생성자에 드러나는가? | 생성자와 순수 단위 테스트 |
| 공유 빈에 요청별 가변 상태가 있는가? | 필드 목록·동시 요청 경로 |
| 어노테이션 호출이 실제 프록시를 지나는가? | 호출 그래프·실제 활성 상태 테스트 |
| HTTP DTO에 사용자가 조작하면 안 되는 필드가 있는가? | owner·가격·권한 필드의 입력 경로 |
| 401·403·400의 발생 계층을 구분하는가? | 실제 HTTP 요청과 필터·MVC 경계 |

| 질문 | 기록할 근거 |
| --- | --- |

## 실패 주입 연습

1. 재고 감소 뒤 Outbox INSERT를 실패시킨다. 예약·재고·Outbox의 최종 상태를 예상하고 검사한다.
2. commit 직후 응답을 잃은 것으로 가정해 같은 키를 재전송한다. 중복 차감이 없어야 한다.
3. Outbox 발행 후 완료 표시 전에 작업자를 종료한다. 중복 수신의 업무 효과를 검사한다.
4. 캐시를 중단한다. DB 대기열과 거절 정책을 관찰한다.
5. 종료 중인 인스턴스로 신규 요청이 들어오는지 확인한다. readiness와 라우팅 전파를 함께 본다.

3~5번은 첨부 앱만으로 완료되는 실험이 아니며 해당 인프라를 구성해야 한다. 미실행 결과를 성공으로 적지 않는다.
