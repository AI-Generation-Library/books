# 학습 경로

| 목표 | 권장 순서 | 완료를 확인할 결과 |
| --- | --- | --- |
| 첫 서버 만들기 | 1~5 → 6~10 → 11~15 | CLI와 HTTP 예제를 실행하고 실패를 설명한다. |
| 데이터가 있는 API | 앞 경로 → 16~20 → 33~34 | 인증·소유권·DB 제약·트랜잭션 경계를 설명한다. |
| 비동기 서비스 | 6~10 복습 → 21~24 → 35 | 재시도·중복·파일·상태 조회를 연결한다. |
| 성능과 운영 심화 | 7·15·17 복습 → 25~32 → 36 | 측정·자원 제한·종료·확장 계획을 작성한다. |

각 파트 뒤에는 정상 동작 하나와 실패 상황 하나를 직접 재현한다. 성공 출력만 따라 쓰는 대신 입력을 바꾸고 어디서 거부되는지 본다. 기본 테스트가 실제 DB와 Redis를 대신하지 않는다는 점을 유지한다.

통합 프로젝트부터 보고 싶다면 예제 README로 메모리 모드를 실행한 다음, 인증 → 업로드 → dispatcher → 분석 → 조회 순으로 코드를 읽는다. 이해가 막히는 실행 원리는 해당 장으로 돌아간다.

운영 경험자는 25~32장을 먼저 읽을 수 있지만 CommonJS·ESM과 이벤트 루프의 문맥 차이를 알고 있어야 한다. 오래된 Node.js 상식을 현재 릴리스에 그대로 적용하지 말고 공식 문서의 버전과 실험 조건을 확인한다.
