# 핵심 용어

| 용어 | 의미 |
| --- | --- |
| 런타임 | 언어 엔진에 I/O·전역 API·프로세스 수명 관리를 더한 실행 환경. |
| V8 | JavaScript 실행과 객체 메모리 관리를 담당하는 엔진. |
| libuv | 이벤트 통지·이벤트 루프와 일부 작업의 스레드 풀 등을 제공하는 라이브러리. |
| 이벤트 루프 | 예약된 I/O·타이머 등의 후속 작업을 적절한 단계에서 처리하는 실행 구조. |
| 마이크로태스크 | Promise 반응·queueMicrotask 등과 연결된 후속 실행 단위. I/O 콜백 큐와 동일하지 않다. |
| 블로킹 | 호출 흐름이나 실행 자원이 완료까지 진행하지 못하는 상태. 동기 계산은 이벤트 루프를 점유할 수 있다. |
| 동시성 | 여러 작업의 진행을 겹쳐 관리하는 성질. |
| 병렬성 | 여러 실행 자원에서 같은 시간에 계산하는 성질. |
| Promise | 비동기 작업의 최종 결과 또는 실패를 표현하는 객체. |
| AbortSignal | 작업에 취소 의도를 전달하는 협력적 신호. 커밋된 변경을 자동 롤백하지 않는다. |
| ESM | import/export를 사용하는 표준 모듈 시스템. |
| CommonJS | require/module.exports를 사용하는 Node.js의 기존 모듈 방식. |
| 잠금 파일 | 직접·전이 의존성의 설치 트리와 무결성 정보를 기록한 파일. |
| 전이 의존성 | 직접 설치한 패키지가 다시 의존하는 패키지. |
| Buffer | 바이트 데이터를 다루는 Node.js 객체. |
| 코드포인트 | Unicode가 정의한 문자 코드 값. 화면의 한 글자 묶음과 다를 수 있다. |
| 그래핌 | 사용자가 하나의 글자로 인식하는 문자 묶음. |
| 스트림 | 데이터를 청크로 읽고 쓰며 처리하는 인터페이스. |
| 백프레셔 | 소비자의 처리 속도에 맞춰 생산자의 전송량을 조절하는 흐름 제어. |
| highWaterMark | 스트림 버퍼링 기준. 전체 프로세스 메모리의 절대 상한은 아니다. |
| 미들웨어 | 요청·응답 처리 사이에서 공통 정책을 수행하고 다음 처리로 연결하는 함수. |
| 멱등성 | 같은 업무를 반복해도 요구하는 최종 효과가 달라지지 않는 성질. |
| 인증 | 요청자가 누구인지 확인하는 과정. |
| 인가 | 그 사용자가 해당 자원·행동에 접근할 수 있는지 확인하는 과정. |
| 세션 | 서버가 인증 상태와 만료·사용자 관계를 유지하는 기록. |
| KDF | 비밀번호 등에서 계산 비용을 가진 키를 유도하는 함수. 비밀번호 저장에서는 개별 salt와 함께 쓴다. |
| 트랜잭션 | 여러 DB 변경을 하나의 업무 단위로 커밋·롤백하는 경계. |
| 격리 수준 | 동시 트랜잭션의 읽기·쓰기 관찰 규칙. |
| 연결 풀 | 재사용할 DB 연결의 수와 수명을 관리하는 구성. |
| outbox | 업무 변경과 같은 DB 트랜잭션에 외부 전달 의도를 저장하는 패턴. |
| 최소 한 번 전달 | 전달 보장을 위해 중복이 생길 수 있는 메시지 처리 성질. |
| stalled | 큐 소비자가 작업 잠금을 유지하지 못해 다시 처리될 수 있는 상태. |
| TTL | 값의 만료 기한. 즉시 일관성을 보장하는 기능은 아니다. |
| 캐시 스탬피드 | 인기 캐시 만료·미스가 원본 요청 폭주로 이어지는 현상. |
| SSE | HTTP로 서버에서 클라이언트로 이벤트를 보내는 단방향 스트리밍 방식. |
| WebSocket | 연결 위에서 양방향 메시지를 주고받는 통신 프로토콜. |
| RSS | 운영체제 관점에서 프로세스가 점유하는 상주 메모리 지표. |
| 힙 | 엔진이 객체 등을 관리하는 메모리 영역. 전체 RSS와 같지 않다. |
| p99 | 관측 지연값의 약 99%가 그 이하인 백분위 지표. 샘플과 측정 조건에 영향을 받는다. |
| closed-loop 부하 | 응답을 받은 뒤 다음 요청을 생성하는 방식. 서버가 느려지면 도착률도 줄 수 있다. |
| liveness | 프로세스가 살아 응답할 수 있는지 확인하는 상태. |
| readiness | 새 트래픽을 받을 준비가 되었는지 확인하는 상태. |
| graceful shutdown | 신규 접수를 멈추고 진행 중 작업과 자원을 기한 내 정리하는 종료 절차. |
| expand-contract | 이전·새 코드가 공존할 수 있도록 스키마 변경을 여러 단계로 나누는 전략. |
