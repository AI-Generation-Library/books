# 실습 기준과 읽는 방법

## 이 책의 흐름

1부에서 실행 환경과 모듈을, 2부에서 비동기와 파일·스트림을 이해한다. 3~5부는 HTTP·타입·테스트·데이터·인증·큐·실시간 통신을 연결한다. 6부는 실행 자원과 성능을 측정하고 7부는 배포·종료·확장을 다룬다. 8부는 같은 개념을 하나의 서비스로 통합한다.

각 장의 실습 명령은 별도 표시가 없으면 `examples` 디렉터리에서 실행한다. `fundamentals`의 짧은 예제는 개념 실험이고 `src`는 종합 프로젝트다. 본문의 코드 일부는 흐름을 설명하는 조각이며, 바로 실행할 파일은 링크와 실행 명령으로 구분한다. 제공한 전체 예제 파일과 잠금 파일을 기준으로 재현한다.

## 버전과 셸

집필 확인일은 2026-10-14(Asia/Seoul)다. Windows에서 Node.js 24.18.0, npm 11.16.0, Python 3.12.12로 확인했다. Node.js 24 계열 공식 문서는 패치 업데이트를 반영할 수 있으므로 날짜와 설치 버전을 함께 기록한다. 최신 보안 패치 적용 후에도 예제를 다시 검사한다.

Node.js 명령 자체는 여러 OS에서 같지만 환경 변수 설정과 신호 전달은 셸·OS마다 다르다. 예제 README에는 PowerShell을 기준으로 썼다. Windows 로컬 실행은 Linux 컨테이너의 파일 권한과 SIGTERM 동작 검증을 대신하지 않는다.

## 코드와 테스트의 범위

메모리 모드는 외부 서비스 없이 전체 요청 흐름을 실행하도록 만들었다. PostgreSQL·Redis 모드는 별도 어댑터·SQL·Compose·통합 테스트를 제공한다. 집필 환경에서 실제 외부 서비스 실행은 확인하지 못했다. TypeScript 검사는 독립 예제 범위이고 모든 JavaScript 소스를 타입 검사했다는 뜻이 아니다.

캐시·멀티파트·WebSocket·분산 추적은 원리와 설계 범위로 설명하며 종합 프로젝트의 구현 기능과 구분한다. 파일 처리 결과는 바이트·Unicode 코드포인트·LF 기준 줄 수다. 사람 눈에 보이는 글자 묶음 수나 단어 수와 다르다.

## 독립적인 기여를 위한 기록

코드를 실행했다면 OS·버전·명령·실제 결과를 남긴다. 문법 검사·메모리 구현 테스트·실제 외부 서비스 테스트·사람 검수는 각각 다르다. 확인하지 않은 범위를 성공으로 표시하지 않는다. 수정할 때는 원고·실행 파일·해설·다운로드를 함께 갱신한다.
