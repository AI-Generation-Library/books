# 파일 처리 서비스의 설계와 한계

## 책임

API가 세션·소유권·요청 한도·업로드를 검사하고 작업을 접수한다. DB의 queued 전이와 outbox 삽입은 한 트랜잭션이다. dispatcher는 큐 추가 후 outbox를 삭제한다. 큐 전송 이후 삭제 전에 종료되면 재전송될 수 있다. worker는 불변 UUID 파일을 분석하고 결과를 저장한다.

작업 상태는 uploading·queued·processing·retrying·completed·failed다. completed는 실패 상태로 되돌리지 않는다. 동일 입력의 통계 계산·결과 저장은 멱등적으로 설계했지만 실행 횟수 exactly-once를 보장하지 않는다. 결제·발송처럼 외부 부수 효과가 있는 작업에는 별도 설계가 필요하다.

## 파일 계약

최대 1MiB UTF-8 텍스트. 바이트 수·Unicode 코드포인트 수·LF 기준 줄 수를 반환한다. 빈 파일은 0줄, 마지막 개행이 없어도 마지막 줄을 센다. 그래핌·단어 개수는 아니다. 스트리밍 TextDecoder로 청크 경계의 한글·이모지를 처리하고 잘못된 UTF-8은 실패한다. 저장 이름은 서버 UUID이며 파일명 입력을 경로에 쓰지 않는다.

## 두 모드

메모리 모드는 프로세스 내 Map과 제한된 실행 작업 집합을 사용한다. 사용자가 계속 접수하면 outbox·사용자·세션·파일 총량은 증가할 수 있다. 내구성과 무제한 운영을 위한 구현이 아니다.

production 모드는 PostgreSQL 저장소·Redis/BullMQ·별도 worker를 사용하는 구성 이름이다. 이 구현의 외부 서비스 실행 여부는 검증 안내를 따른다. 공개 서비스 준비 완료를 의미하지 않는다. Compose 파일은 한 호스트의 학습 환경이며 실제 운영 배포 문서가 아니다.

## 현재 구현한 보호

- 요청별 UUID와 구조화 로그. 비밀번호·토큰·본문·접속 비밀은 로그에 기록하지 않는다.
- scrypt-v1(N=32768,r=8,p=3) 비밀번호 해싱, 개별 salt, 최대 동시 KDF 2건.
- 32바이트 난수 세션과 토큰 해시 저장, 만료·로그아웃.
- GET·SSE 소유권 검사. 미존재와 권한 없음은 404.
- 실제 업로드 바이트 제한·서버 UUID·배타적 새 파일 생성·전송 실패 시 부분 파일 정리.
- PostgreSQL 매개변수 쿼리·제약·연결 획득/쿼리 기한, 풀 오류 이벤트 처리.
- outbox 전송 재시도·동일 jobId·완료 결과 보존.
- SSE 연결 종료 정리·느린 수신자 연결 종료·최대 30초 후 재접속 방식.
- 종료 기한·readiness·자원 close 경로.

## 운영에 추가할 항목

- 업로드 POST 자체의 멱등 키. 현재 같은 파일을 재전송하면 새 작업을 만든다.
- 계정 확인·비밀번호 재설정·계정 복구·MFA·세션 목록과 만료 행 정리.
- 공유 요청 제한·계정별 저장 총량·전역 업로드 동시성·outbox 접수 상한.
- 오래된 uploading·processing 점검, 고아 파일 정리, 보관 기간과 삭제 정책. 파일과 DB는 하나의 원자적 자원이 아니다.
- 다중 호스트용 객체 저장소·파일 내용 무결성·권한. 현재는 동일 호스트 공유 볼륨.
- TLS·운영 비밀 주입·접속 권한·이미지 갱신·백업 복원·배포·장애 실험.
- 영속 이벤트 이력·커서 재생이 필요한 경우 별도 구현. 현재 SSE는 최신 상태 조회다.
- 메트릭 수집기·분산 추적 exporter·경보. 현재는 요청 로그와 측정 예제만 구현한다.

이 목록은 완료한 운영 검증 목록이 아니다. 테스트와 검증 안내의 실제 결과를 기준으로 평가한다.
