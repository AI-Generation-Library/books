# 29장. 실수 점검과 제한 시간 운영

제한 시간 연습에서는 데이터와 상태 오류를 빨리 찾고 필요한 작업을 완료해야 한다. 손이 빠른 것보다 요구조건과 단계 간 연결을 정확히 유지하는 것이 중요하다. 처음 실행부터 종료 확인까지의 시간을 기록한다.

## 1. 반복 오류를 원인으로 묶기

| 증상 | 우선 확인 | 수정 방향 |
| --- | --- | --- |
| 파일 없음 | 작업 위치·파일명·확장자 | 실제 경로 확인 |
| KeyError | 열 이름·공백·이전 대입 | columns와 요구조건 대조 |
| 문자열 입력 오류 | 자료형·범주 변환 | 정해진 인코딩 |
| NaN·무한값 | 원자료·대체·변환 결과 | 학습 범위 안의 처리 |
| 열 수 불일치 | 원핫 상태·열 순서 | 같은 변환 재사용 |
| 길이 불일치 | 행 필터·정렬·타깃 대응 | 같은 인덱스·마스크 사용 |
| NotFittedError | 실제 학습 객체·실행 순서 | 필요한 fit 확인 |

오류 메시지를 지우는 것만으로 문제가 해결되지 않는다. 코드가 작동해도 다른 행과 타깃이 연결되는 판단 오류가 있을 수 있다.

## 2. 실행 가능한 확인 묶음

```python
import numpy as np
from lab import split_task, preprocessor

X_train, X_val, X_test, y_train, y_val, y_test = split_task()
assert X_train.index.equals(y_train.index)
assert set(X_train.index).isdisjoint(X_val.index)
assert set(X_train.index).isdisjoint(X_test.index)
assert "churn" not in X_train.columns
prep = preprocessor()
train = prep.fit_transform(X_train)
val = prep.transform(X_val)
assert train.shape[1] == val.shape[1]
assert np.isfinite(train).all() and np.isfinite(val).all()
assert len(y_train) == len(train)
print("Input, split and transformation checks passed")
```

이런 확인은 의도한 전처리·형태를 점검하지만 모든 누수·도메인 오류를 자동으로 잡지는 않는다. 공식 문항의 출력·셀 규칙이 있으면 디버깅 코드를 포함할 범위도 확인한다.

## 3. 시간 배분 연습

자체 모의고사에서는 처음 5분 요구조건 확인, 약 25분 분석, 25분 전처리, 25분 모델·평가, 마지막 10분 검토처럼 시작할 수 있다. 이는 저자의 연습 예시이며 공식 권장 시간이나 보장 전략이 아니다. 실제 문항 난이도와 진행 상황에 맞춰 조정한다.

막힌 문항이 후속 작업의 필수 입력인지 확인한다. 단순한 출력 이름 문제와 데이터 로딩 실패는 영향이 다르다. 오래 걸리는 탐색을 시작하기 전에 요구조건과 남은 시간을 본다. 불필요한 대형 탐색을 기본 행동으로 넣지 않는다.

## 4. 마지막 검토

타깃·입력, 분할, 학습한 변환, 모델·설정, 예측·평가와 저장 파일을 확인한다. 한 셀·파일명·확장자 등 제출 조건은 최신 공식 가이드와 화면 지시에 따른다. 새 커널의 전체 재실행은 평소 학습에서 충분히 연습하며 시험 중 재시작·재실행은 공식 조건과 남은 시간을 고려한다.

장애가 발생하면 임의 우회·외부 도움을 구하지 않고 공식 감독·지원 경로에 문의한다. 제한적 오픈북의 허용 범위를 시험 당일 추측하지 않도록 사전에 확인한다.

## 5. 오답을 다음 학습으로

오답노트에는 실패 단계, 원인, 수정과 재발 방지 확인을 적는다. 문법·형태 오류는 작은 독립 예제로, 판단 오류는 자료 사전·요구조건 설명으로 복습한다. 점수만 기록하면 같은 원인이 반복될 수 있다.

## 연습과 해설

1. 입력 형태 확인을 통과하면 모든 누수가 없는가? **해설:** 아니다. 미래 정보와 자료 정의·테스트 재사용 등은 별도 검토해야 한다.
2. 마지막 검토에서 높은 점수를 위해 모델을 바꿔도 되는가? **해설:** 지정 모델·설정과 제출 조건을 먼저 확인한다.
