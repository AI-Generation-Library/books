# 02장. 나에게 맞는 학습계획 세우기

같은 교재라도 Python 초보자와 업무에서 pandas를 쓰는 사람의 출발점은 다르다. 정해진 기간을 합격 보장처럼 사용하지 말고, 실제로 수행할 수 있는 작업으로 준비도를 판단한다. 읽어 본 코드와 도움 없이 다시 작성할 수 있는 코드는 다르다.

## 1. 다섯 작업으로 진단하기

빈 노트북에서 CSV를 읽고, 조건으로 행을 선택하고, 결측을 확인하고, 훈련·테스트를 나누고, 간단한 모델을 평가해 본다. 타깃과 입력의 차이를 설명하고 배열의 행·열 수도 확인한다. 작업마다 혼자 가능, 문서가 있으면 가능, 아직 어려움으로 기록한다.

| 단계 | 혼자 확인할 수행 | 어려울 때 돌아갈 장 |
| --- | --- | --- |
| 기초 | 리스트·배열·DataFrame의 형태 설명 | 3~4장 |
| 분석 | 필터·집계·결측·그림 | 5~9장 |
| 전처리 | 분할 후 변환의 학습·적용 | 10~15장 |
| 모델링 | 학습·예측·적절한 지표 | 16~25장 |
| 실전 | 조건·변수명·출력을 끝까지 확인 | 26~30장 |

## 2. 네 단계의 학습 묶음

기초와 탐색, 전처리, 모델링, 통합·모의 연습을 순서대로 공부한다. 예시로 네 주에 한 묶음씩 배정할 수 있지만 기간은 가용 시간과 준비도에 따라 조정한다. 하루 시간을 늘리는 것보다 다음 단계로 갈 수행 기준을 세우는 것이 중요하다.

첫 묶음의 완료는 데이터를 읽고 필요한 행·열과 품질을 확인하는 것이다. 두 번째는 누수 없이 입력을 만드는 것이다. 세 번째는 문제에 맞는 모델·손실·평가를 선택하는 것이다. 마지막은 새 데이터에서 처음부터 다시 실행하는 것이다.

## 3. 한 번의 학습을 네 활동으로 나누기

개념을 읽은 뒤 예제를 실행한다. 이어서 값·열·조건 하나를 바꿔 결과를 예상하고 확인한다. 마지막에는 책을 닫고 핵심 흐름을 다시 작성한다. 복사 실행만 하면 함수의 인수나 입력 형태가 바뀔 때 멈출 수 있다.

오류가 나면 마지막 줄을 지우고 다시 실행하기보다 오류 종류, 실패 줄과 입력 형태를 기록한다. 오답노트에는 틀린 코드, 이유, 수정 코드, 재발을 막을 확인을 남긴다. 문법 오류와 판단 오류를 구분한다.

## 4. 복습은 실패 지점에 맞추기

인코딩 후 열 수가 다르면 12·15장을 다시 보고, 테스트 데이터에서 `fit`했다면 13~14장의 흐름을 설명한다. 손실함수 조합이 틀렸다면 23장의 라벨·출력 표를 다시 작성한다. 모든 장을 같은 횟수로 읽을 필요는 없다.

이미 익숙한 사람은 통합 실습으로 진단하고 필요한 기초로 돌아가도 된다. Python 초보자는 모델링을 서두르기보다 자료형과 선택·집계 연습을 충분히 한다. 모의시험 결과만 보지 말고 로딩, 전처리, 모델과 검토의 시간을 나눠 기록한다.

## 5. 공식 자료와 책의 역할

시험 방식과 자료 사용·환경·제출 규정은 공식 안내로 확인한다. 이 책의 자체 문제로 코딩 흐름을 반복하고, 공식 공개 샘플은 제공 조건에 맞춰 직접 확인한다. 공개 샘플을 그대로 책의 문제로 재배포하지 않는다.

[학습 체크리스트](../appendices/study-plan.md)를 사용해 완료한 수행과 다시 확인할 항목을 남긴다. 기한에 맞춰 빈칸을 모두 체크하는 것보다, 새 조건에서 반복할 수 있는지를 확인한다.

## 연습과 해설

1. 코드가 실행되지만 왜 `fit_transform`을 썼는지 설명하지 못한다. 다음 활동은? **해설:** 훈련에서 통계를 학습하는 단계와 다른 데이터에 적용하는 단계를 설명하고 직접 분리해 실행한다.
2. 학습 시간을 모두 모델 탐색에 쓰면 어떤 부분이 빠지는가? **해설:** 요구사항 읽기, 자료 품질·누수 점검, 실행 순서와 저장·검토가 빠질 수 있다.
