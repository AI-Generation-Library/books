# 14장. 하이브리드 검색과 순위 결합

## 학습 목표

- 서로 다른 검색 점수를 무리하게 직접 더하지 않는다.
- 후보 예산·중복·RRF 설정을 명시한다.

## 두 검색기가 놓치는 것이 다를 때

키워드 검색은 정확 단어에 강하고 dense는 재표현된 의미에 도움을 줄 수 있다. 둘을 결합하면 누락을 보완할 수 있지만 항상 품질과 비용의 최적점은 아니다. 같은 오류를 내는 검색기를 여러 개 붙인다고 관련 근거가 새로 생기지는 않는다.

BM25 점수와 코사인 점수는 범위가 다르다. 그대로 더하면 한쪽 값의 스케일이 결과를 지배할 수 있다. 점수 보정·가중 결합도 가능하지만 데이터와 검증이 필요하다. RRF는 점수 대신 순위로 결합하는 단순 기준선이다.

## RRF 손으로 계산하기

```text
fused_score(d) = 각 검색 순위 r에 대해 1 / (c + r)의 합
c=60, A가 두 검색에서 각각 1위와 3위:
score(A)=1/61 + 1/63
```

c는 분모의 순위 완화 상수다. 검색 상위 k개 개수와 같은 값이 아니다. 후보 수·완화 상수·융합 후 반환 수를 별도 설정한다. 예제는 각 검색 최대 20개를 융합하고 사용자 요청의 limit만큼 돌려준다.

같은 청크가 여러 검색에 나오면 하나의 객체로 합치고 각 순위의 기여를 더한다. 한 검색 결과 안에서 같은 청크가 중복되었다고 점수를 두 번 더하지 않는다. 동점 때는 안정적인 청크 ID로 정렬해 재현성을 유지한다.

## 문서 중복과 의미 중복

청크 ID 중복 제거는 같은 문서의 겹치는 청크나 내용이 비슷한 여러 문서를 제거하지는 않는다. 상위 결과가 한 문서의 중첩 청크로 가득하면 다른 관점을 잃을 수 있다. 문서별 후보 제한·MMR·부모 문서 확장 같은 후속 정책을 비교한다.

검색 후보를 늘리면 Recall이 좋아질 수 있지만 리랭킹·컨텍스트 비용이 커진다. 최종 생성에 넣을 근거 수는 검색 후보 수와 다르게 둔다. 하나의 k 값으로 두 예산을 묶으면 실험을 해석하기 어렵다.

## 평가와 거절

RRF 점수는 합친 검색 수와 순위에 의존한다. 벡터 유사도 0.7 임계값을 RRF 점수에도 적용하면 안 된다. 질문의 답변 가능성은 별도 정책으로 검증한다. 기본 데모는 lexical 겹침을 보수적 신호로 쓰지만 의미적 answerability 모델이나 정답 확률은 아니다.

작은 실제 실험에서는 hybrid dev MRR이 1.0이었지만 BM25도 같았다. 따라서 이 자료에서 hybrid가 반드시 더 좋은 선택이라고 결론 내릴 수 없다. 지연·운영 비용과 실패 질문을 함께 본다.

## 실습과 평가

tests/test_core.py의 RRF 기여도·중복 테스트를 읽고 1/61+1/61을 직접 계산한다. 서로 다른 검색이 한 문서를 지지할 때와 단일 검색에만 나올 때를 비교한다.

동일 dev·test에서 각 방식의 질문별 순위를 확인한다. test에 맞춰 상수와 후보 수를 반복 조정하지 않는다.
