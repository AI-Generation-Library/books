# 19장. 다단계 질문과 Multi-hop Retrieval

## 학습 목표

- 여러 근거를 연결해야 하는 질문을 분해한다.
- 반복 검색의 종료·오류·비용을 제어한다.

## 한 번의 검색으로 부족한 질문

어떤 정책의 적용 대상과 그 대상의 예외를 서로 다른 문서에서 찾아야 할 수 있다. 첫 검색 결과에 나온 개체를 이용해 다음 검색을 수행하는 것이 도움이 된다. 질문을 여러 하위 질문으로 나누고 근거를 모으는 방식도 있다.

그러나 단계가 늘면 초반의 잘못된 개체 추정이 이후 모든 검색을 잘못 이끌 수 있다. 원 질문·중간 질의·검색된 실제 근거·아직 모르는 항목을 구분해 기록한다. 중간 생성 문장을 검증된 사실로 승격하지 않는다.

## 근거 계획과 연결

예를 들어 가상 질문이 출장비 기한과 승인 절차를 비교한다면 두 사실에 필요한 문서 ID와 원문 구간을 각각 확보한다. 같은 단어가 나온다는 이유로 다른 제도의 기간을 가져와 합치지 않는다. 수치의 단위·대상·유효 시점을 함께 확인한다.

```text
원 질문 → 필요한 사실 목록
각 사실 → 허용된 검색 → 근거와 출처
근거 충분성 확인 → 추가 검색 또는 근거 부족 응답
최종 답변 → 주장별 근거 연결
```

분해가 늘 좋은 것도 아니다. 하나의 명확한 문서 질문을 여러 호출로 나누면 지연과 오류만 늘 수 있다. 고정 파이프라인 기준선과 실제 복합 질문에서 비교한다.

## 종료 조건

최대 검색 횟수·전체 기한·최대 후보·컨텍스트 예산을 정한다. 새 근거가 나오지 않거나 필요한 사실을 확인하지 못하면 멈추고 한계를 설명한다. 모델이 더 찾아보자고 반복한다고 무한히 도구를 호출하게 두지 않는다.

검증 단계도 같은 근거를 다른 표현으로 반복하는 자기 확인이 될 수 있다. 새로운 원본이 추가되었는지, 필요한 조건이 실제로 충족되었는지 측정한다. LLM이 스스로 확신한다고 근거가 늘어난 것은 아니다.

## 평가 단위

최종 정답뿐 아니라 하위 질문의 적절성·각 단계 검색 Recall·원본 연결·호출 수·전체 비용·지연을 기록한다. 단계별 근거가 모두 맞아도 연결 추론에서 틀릴 수 있으므로 최종 주장도 별도 평가한다. 권한이 없는 중간 문서를 발견하면 접근 범위를 넓히는 대신 답변 가능한 범위를 제한한다.

이 장은 설계와 제한된 실행 구조를 설명한다. 기본 서비스가 자동 Multi-hop 계획과 반복 도구 선택을 구현한 것으로 표시하지 않는다. Agentic RAG의 일반 제어는 34장에서 이어 간다.

## 실습과 평가

가상 문서 두 개를 연결해야 하는 질문을 만들고 필요한 사실·근거 ID를 사람이 먼저 작성한다. 한 번 검색과 단계별 검색을 비교할 평가 계획을 만든다.

종료 예산을 2회로 정한 경우 근거를 못 찾았을 때의 응답을 설계한다. 중간 가정이 틀린 경우를 negative로 추가하고 최종 문장만 보는 평가의 누락을 확인한다.
