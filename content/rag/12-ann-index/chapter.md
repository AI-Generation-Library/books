# 12장. 벡터 인덱스의 내부 원리

## 학습 목표

- 정확 최근접 검색과 근사 검색의 손실을 구분한다.
- 인덱스 속도·메모리·검색 품질을 함께 조정한다.

## 정확 검색을 기준으로 둔다

모든 문서 벡터와 질문 벡터의 거리를 계산해 정렬하면 정확 검색 결과를 얻을 수 있다. 문서 수와 차원이 커지면 계산·메모리 접근 비용이 커진다. 근사 최근접 이웃 검색은 탐색 범위를 줄여 더 빠르게 후보를 찾는 대신 정확 상위 이웃을 일부 놓칠 수 있다.

예제의 dense 함수는 권한 있는 청크 전체를 정확히 순회한다. ANN을 구현하거나 HNSW의 성능을 검증한 코드가 아니다. 작은 데이터에서는 읽기 쉬운 정확 검색이 기준선이 되고, 큰 실험에서 ANN 결과와 비교하는 기준도 된다.

## HNSW와 IVF의 직관

HNSW는 벡터 사이의 근접 관계를 여러 층의 그래프로 연결해 탐색한다. 연결과 탐색 폭을 늘리면 검색 품질이 좋아질 여지가 있지만 메모리·구축·질의 비용이 커진다. 구축 설정과 질의 시 탐색 설정은 다른 단계다.

IVF는 공간을 여러 목록으로 나누고 질문과 가까운 목록 일부를 탐색한다. 목록 수와 검색할 목록 수를 조절한다. 데이터 분포와 학습·재구축 조건을 확인한다. 양자화는 벡터 표현의 저장 비용을 줄이는 대신 거리 근사 오차를 추가할 수 있다.

## 두 종류의 Recall

ANN Recall은 정확 검색의 상위 이웃을 얼마나 회수했는지 묻는다. 업무 검색 Recall은 사람이 관련하다고 정한 근거를 얼마나 찾았는지 묻는다. ANN이 정확 코사인 순위를 완벽히 재현해도 임베딩 모델 자체가 질문의 정답 문서를 놓칠 수 있다.

| 질문 | 비교 기준 |
| --- | --- |
| ANN이 이웃을 놓쳤는가 | 같은 벡터·거리의 정확 검색 |
| 검색이 필요한 근거를 찾았는가 | 질문별 qrels |
| 최종 답변이 맞는가 | 근거·정답·사람 기준표 |

이 세 값을 하나의 정확도라는 이름으로 섞지 않는다. 모델과 청킹을 바꾼 상태에서 ANN 설정도 동시에 바꾸면 원인이 불명확해진다.

## 필터와 갱신

권한·날짜·tenant 필터가 있으면 검색 후보의 분포가 달라진다. 인덱스 내부에서 필터가 적용되는 시점에 따라 반환 수와 Recall이 달라질 수 있다. 결과가 k개보다 적다고 단순히 모델 문제로 판단하지 않는다.

삽입·삭제·복제·재구축 중에도 인덱스 revision을 추적한다. 작은 균등 난수 벡터 시험만으로 실제 문서 규모와 분포의 지연·Recall을 예측하지 않는다. 데이터 크기·차원·필터 선택성·동시 질의를 함께 실험한다.

## 실습과 평가

기본 dense 구현의 전체 순회 비용을 읽고 문서 수 N과 차원 d에 따라 계산이 어떻게 증가하는지 설명한다. 같은 벡터를 ANN 저장소에 넣는 확장 실습에서는 정확 검색과 이웃 겹침을 측정한다.

이번 책은 로컬 정확 검색과 실제 임베딩을 실행했다. pgvector HNSW/IVF 인덱스 실행과 대규모 ANN 벤치마크는 미검증으로 구분한다.
