# 37장. 도메인 특화와 검색 모델 개선

## 학습 목표

- 데이터·검색·모델 중 병목에 맞는 개선을 선택한다.
- 학습·검증 누출과 hard negative 품질을 관리한다.

## 모델 학습 전에 확인할 것

전문 용어를 놓쳤다는 이유만으로 파인튜닝부터 시작하지 않는다. 파싱·토큰화·동의어·문서 제목·필터·최신성·후보 수가 원인일 수 있다. 정확 코드에는 keyword 기준선이 유리할 수 있다. 실패 trace로 병목을 먼저 좁힌다.

모델 적응이 필요하면 질의-관련 문서 쌍과 비관련 후보를 만든다. 실제 사용자 표현과 문서의 대응을 포함하고, 필요한 예외와 부정 조건을 유지한다. 합성 데이터는 오류·쉬운 표현·모델 편향을 검토한다.

## 임베딩과 리랭커 학습

대조 학습은 질문과 관련 문서를 가깝게, 비관련 문서를 멀게 구분하도록 도울 수 있다. hard negative는 비슷하지만 답이 아닌 자료여야 한다. 라벨이 빠진 실제 관련 문서를 negative로 넣으면 잘못된 구분을 학습할 수 있다.

리랭커는 후보 쌍·순위·관련성 등급으로 학습할 수 있다. 학습 문서와 평가 문서가 거의 같으면 일반화 성능을 과대평가할 수 있다. 문서군·주제·시간별 분할과 중복 검사를 유지한다.

## 생성 모델 적응

답변 형식·도메인 표현·도구 사용을 맞추는 학습과 최신 사실을 제공하는 검색은 다른 역할이다. 파인튜닝 모델이 정책 문구를 외웠다고 삭제·개정·권한을 자동 반영하지는 않는다. 사실의 원본과 갱신 경로를 유지한다.

교사 모델의 답변을 학생 모델에 전달하는 증류도 오류와 데이터 사용 조건을 검토해야 한다. 교사 출력과 원문 지지를 구분하고, 평가 데이터를 학습에 섞지 않는다. 학습 비용 외에 새 embedding 인덱스를 다시 만드는 비용도 계산한다.

## 도입 판단

학습 전후 같은 고정 평가에서 질문 유형별 품질·지연·저장량·색인 비용을 비교한다. 전문 영역이 좋아졌지만 일반 질문이 크게 나빠질 수 있다. 유지보수·재학습·추가 라벨링·롤백을 포함해 선택한다.

이 책은 공개 모델 추론과 비교를 실행했다. 임베딩·리랭커·생성 모델의 파인튜닝·증류·대규모 학습은 수행하지 않았고 그 절차를 완료한 결과처럼 표시하지 않는다.

## 실습과 평가

실패 질문을 파싱·키워드·임베딩·리랭킹·생성으로 분류한다. 모델 학습 없이 해결할 수 있는 가설부터 dev에서 시험한다.

도메인 학습 실험 계획에는 데이터 권리·중복·분할·hard negative 검토·기준선·운영 재색인 비용을 포함한다.
