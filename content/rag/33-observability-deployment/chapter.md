# 33장. 관측·배포·품질 모니터링

## 학습 목표

- 운영 장애와 품질 변화를 다른 신호로 관찰한다.
- 배포 산출물·색인·평가 결과를 연결한다.

## 요청이 성공해도 답이 틀릴 수 있다

HTTP 200과 낮은 서버 오류율만으로 RAG 품질을 평가할 수 없다. 검색 결과가 비어 있거나 오래된 문서를 사용하고, 근거 없는 답을 생성해도 정상 응답일 수 있다. 운영 지표와 품질 지표를 함께 둔다.

단계별 지연·모델 실패·거절 비율·인용 검증 실패·색인 지연·삭제 반영·권한 오류를 관찰한다. 문서 종류·언어·질문 유형에 따라 품질을 나누되 사용자 ID·질문 전체를 메트릭 label로 넣어 시계열 수와 개인정보를 무한히 늘리지 않는다.

## trace와 재현

요청 ID에 문서 snapshot·embedding signature·검색 방식·후보 ID·최종 근거 ID·생성 모델 digest·프롬프트 revision을 연결할 수 있다. 원문 전체를 항상 저장할 필요는 없다. 필요한 재현 정보와 접근·보관 정책을 함께 설계한다.

예제는 안전한 기본 요청 로그와 실행 결과 JSON을 제공한다. OpenTelemetry 수집기·운영 대시보드·경보 시스템을 실제 배포한 구현은 아니다. 프레임워크 검색 어댑터 검증에서는 외부 tracing 전송을 비활성화했다.

## 품질 변화의 원인

사용자의 질문 분포가 바뀌거나 새 용어·언어·문서 양식이 들어오면 기존 평가 평균이 실제 경험을 반영하지 못할 수 있다. 모델·색인·파서·권한 변경과 지표 변화를 함께 본다. 거절 비율 상승이 모델 성능 저하인지 문서 삭제·정상 권한 제한인지 구분한다.

피드백의 좋아요만으로 사실 정확성을 알기 어렵다. 사용자가 유창한 오답을 좋아할 수도 있다. 근거 위치·필요 사실·오류 유형을 확인하는 검토와 연결한다. 피드백을 그대로 학습 라벨로 쓰기 전에 검증한다.

## 배포 전과 롤백

고정 평가셋·보안/삭제 테스트·모델 연결 smoke를 실행하고 코드 커밋과 색인 revision을 기록한다. 새 모델이나 인덱스를 일부 트래픽에 적용할 때 중단 조건과 이전 경로를 준비한다. 코드만 롤백해도 DB·색인·삭제 상태는 자동 복원되지 않는다.

TLS·운영 인증·요청 바이트 제한·비밀 주입·데이터 백업·복원·자원 한도를 배포 환경에서 검증한다. 모델 가중치와 운영 문서를 이미지에 무심코 넣지 않는다. 최신 이미지와 패키지 보안 상태를 확인하고 검증한 산출물을 고정한다.

## 실습과 평가

로컬 서버의 X-Request-ID와 로그를 연결한다. 질문·토큰·본문이 기본 로그에 출력되지 않는지 확인한다. API의 health는 서버 응답 상태이며 모든 모델·문서 품질이 정상이라는 보증은 아니다.

실제 컨테이너·클라우드·TLS·백업 복원·운영 부하·브라우저 시각 QA는 이번 집필에서 수행하지 않았다고 기록한다.
