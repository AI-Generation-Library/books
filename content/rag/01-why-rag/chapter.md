# 01장. RAG는 무엇이고 언제 필요한가

## 학습 목표

- 검색·근거 구성·생성을 별도 단계로 설명한다.
- RAG·파인튜닝·긴 컨텍스트의 선택 조건을 비교한다.

## 답변 전에 자료를 찾는 구조

사용자가 사내 규정의 변경 날짜를 물었을 때 모델의 학습 지식만으로 답하게 하면 그 문서의 존재·최신 버전·사용자 권한을 알기 어렵다. RAG는 질문과 관련된 외부 자료를 찾아 모델 입력에 넣고, 그 자료를 근거로 답하게 하는 구조다. 문서를 모델 파라미터에 새로 학습시키는 과정과 구분한다.

검색 증강 생성이라는 이름 아래에도 다양한 구현이 있다. 초기 연구의 학습 구조와 오늘날 흔한 검색 후 프롬프트 구성 파이프라인이 완전히 같은 것은 아니다. 이 책은 검색→컨텍스트 구성→생성의 명시적인 흐름을 기본으로 삼고, 후반부에서 반복 검색과 에이전트 구조로 확장한다.

```text
색인 흐름: 원문 → 파싱 → 정규화 → 청크 → 검색 인덱스
질문 흐름: 인증 → 권한 범위 → 검색 → 근거 선택 → 생성 → 인용 검증 → 응답
```

두 흐름의 시간축도 다르다. 문서 색인은 갱신 시 수행하고 질문 처리는 요청마다 수행한다. 색인이 오래되면 좋은 모델도 오래된 근거로 답할 수 있다. 삭제와 권한 회수는 단순한 검색 정확도보다 우선하는 데이터 경계다.

## RAG가 해결하는 것과 남는 문제

근거를 찾는 구조는 최신 문서·비공개 지식·출처 표시를 다루는 데 유용하다. 그러나 관련 없는 문서를 검색하거나, 조건이 잘린 청크를 전달하거나, 모델이 근거를 무시하면 답변은 틀릴 수 있다. 인용 링크가 있다는 사실도 해당 문장이 실제로 뒷받침된다는 증명은 아니다.

검색된 문서에는 오래된 정책·서로 충돌하는 설명·악의적인 지시가 들어 있을 수 있다. 문서는 실행 지시가 아닌 데이터로 취급하고 원본·버전·권한을 추적한다. RAG를 붙였으니 환각이 사라졌다는 완료 기준을 사용하지 않는다.

## 다른 접근과 비교하기

| 접근 | 주로 바꾸는 것 | 먼저 확인할 비용과 한계 |
| --- | --- | --- |
| 프롬프트 개선 | 작업 지시와 출력 방식 | 필요한 사실을 입력으로 제공할 수 있는가 |
| 긴 컨텍스트 | 한 번에 제공하는 자료량 | 비용·지연·관련 정보 활용·권한 |
| RAG | 질문별 자료 선택과 갱신 | 검색 누락·색인 수명·근거 품질 |
| 파인튜닝 | 모델의 행동·도메인 적응 | 학습 자료·검증·갱신 비용 |

이들은 조합할 수 있다. 작은 문서 집합은 직접 입력하는 기준선이 합리적일 수 있고, 답변 양식은 파인튜닝으로 맞추면서 사실은 검색할 수 있다. 요구사항과 평가 결과를 먼저 정하고 기법을 선택한다.

## 이 책의 두 출력 모드

외부 모델 없이 실행하는 발췌 모드는 검색·권한·인용·삭제를 검증하기 위한 데모다. 문장을 새로 생성한 LLM 결과로 표시하지 않는다. 실제 모드는 다국어 신경망 임베딩과 로컬 Ollama 생성 모델을 연결한다. 두 모드의 실행 결과와 범위는 검증 안내에 따로 기록한다.

## 실습과 평가

`examples`에서 `python -m ragbook.cli index` 후 `python -m ragbook.cli query "연차 휴가는 연간 며칠인가요?"`를 실행한다. 기본 결과의 generator는 `extractive-demo-not-llm`이다. 문서 ID·버전·원문 범위를 확인한다.

문서와 질문은 저자가 작성한 가상 데이터다. 실제 회사 규정·법률·개인정보를 포함하지 않는다. 같은 질문을 검색 없이 답하는 방식과 비교할 때도 맞아 보이는 문장보다 근거와 검증 가능성을 평가한다.
