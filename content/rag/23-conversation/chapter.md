# 23장. 대화형 RAG와 메모리

## 학습 목표

- 생략된 후속 질문을 검색 가능한 질의로 해석한다.
- 대화 이력·사용자 상태·문서 근거를 분리한다.

## 후속 질문의 생략

사용자가 휴가를 물은 뒤 신청은 언제까지야라고 하면 두 번째 질문만으로는 대상이 모호하다. 대화 문맥을 이용해 휴가 신청 기한을 묻는 독립 질의로 바꿀 수 있다. 그러나 이전 대화의 잘못된 모델 답변을 사실로 믿고 검색하면 오류가 누적될 수 있다.

검색용 독립 질의와 사용자가 실제로 물은 문장을 둘 다 보관한다. 재작성에서 새 수치·날짜·개체를 만들어 넣지 않았는지 확인한다. 대화가 주제를 바꾸었는데 이전 주제를 계속 강제하는 실패도 평가해야 한다.

## 세 종류의 상태

대화 이력은 사용자가 무엇을 말했는지의 기록이다. 사용자 프로필·선호는 별도 권한과 보관 정책을 가진 상태다. 검색 근거는 현재 자료에 연결된 사실 출처다. 세 가지를 하나의 프롬프트 문자열에 무작정 합치면 어떤 값이 검증된 사실인지 알기 어렵다.

이전 답변에 인용이 있더라도 문서가 개정되면 재확인이 필요하다. 대화 요약은 원본 이력을 압축한 파생 자료이므로 요약 오류와 출처 누락을 고려한다. 핵심 정책·권한을 생성 요약만으로 유지하지 않는다.

## 세션과 tenant

서로 다른 사용자의 대화를 전역 목록에 저장하면 정보가 섞일 수 있다. 서버에서 인증된 사용자·tenant·세션 ID를 묶고 요청 본문의 임의 ID가 다른 세션을 읽지 못하게 한다. 로그와 분석용 대화에도 개인정보 최소화·보관·삭제를 적용한다.

사용자가 역할을 바꾸거나 권한이 회수되면 이전 대화에 포함된 민감 근거를 다시 내보낼 수 있는지 정책을 정한다. 과거 프롬프트 캐시·요약·LLM 메모리도 같은 데이터 경계다. 이번 기본 서비스는 대화 상태를 서버에 저장하지 않는 단일 질문 API다.

## 평가하는 방법

단일 질문 평가와 대화 평가를 분리한다. 대명사 해석·주제 변경·정정·오래된 전제·권한 변경·삭제 요청을 시나리오로 만든다. 마지막 문장만 맞는지보다 각 턴의 독립 질의와 실제 검색 근거를 함께 본다.

대화가 길어져도 전체 이력을 무제한 전송하지 않는다. 최근 이력·검증된 상태·관련 근거를 예산 안에 선택하고, 사용자가 이전 말을 정정했을 때 어느 값이 현재 유효한지 명확히 한다.

## 실습과 평가

가상 대화를 만들어 각 턴의 원 질문·독립 질의·필요 근거를 사람이 작성한다. 이력에 잘못된 숫자를 심은 경우 검색이 이를 교정할 수 있는지 평가 계획을 세운다.

현재 예제는 대화 메모리를 구현하지 않았다. 확장할 때는 사용자별 분리·삭제·권한 변경 테스트를 기본 기능보다 먼저 추가한다.
