# 34장. Agentic RAG

## 학습 목표

- 고정 흐름과 동적인 검색 도구 선택을 비교한다.
- 실행 횟수·기한·권한·중간 근거를 제어한다.

## 모델이 검색 시점과 방법을 선택할 때

고정 RAG는 정한 순서로 검색하고 생성한다. Agentic RAG는 모델이 검색 도구를 선택하거나 질의를 분해하고 부족한 근거를 다시 찾을 수 있다. 복잡한 질문에 유용할 수 있지만 호출 수·지연·재현성·오류 누적의 관리가 추가된다.

단순한 정책 질문마다 에이전트를 호출할 필요는 없다. 고정 흐름의 품질과 비용을 기준선으로 두고 복합 질문·다중 소스에서 실제 이득이 있는지 비교한다. 최신 방식이라는 이름이 모든 서비스에 적합하다는 결론은 아니다.

## 상태와 실행 예산

```text
plan → 허용 도구 선택 → 검색 → 근거 점검
                      ↖ 부족하면 제한된 재검색
충분하거나 예산 소진 → 검증된 답변 또는 근거 부족
```

질문·계획·도구 호출·실제 근거·아직 모르는 조건을 구분한다. 최대 호출 수·전체 기한·토큰·비용·후보 수를 정하고 같은 질의만 반복하면 멈춘다. 답을 얻을 때까지라는 무제한 종료 조건을 쓰지 않는다.

## 도구 계약

도구에는 이름·입력 스키마·권한·결과 형식·한도·실패 동작을 정의한다. 검색 도구는 서버 Principal의 범위를 고정한다. 모델이 다른 tenant를 인자로 넣거나 문서가 관리자 도구를 호출하라고 지시해도 허용되지 않아야 한다.

읽기 도구와 외부 전송·업무 변경 도구를 분리한다. RAG의 검색 기능을 확장하다가 생성 모델에 셸과 전체 파일 접근을 조용히 부여하지 않는다. 민감한 행동의 승인과 감사 정책은 도구 계층에서 강제한다.

## 반복 검증의 한계

모델이 자기 답변을 다시 읽고 맞다고 말하는 것은 새 근거가 아니다. 필요한 원문이 추가되었는지와 조건이 확인되었는지를 검증한다. 중간 추론을 사실 원장으로 저장하지 않고, 최종 주장까지 원문에 연결한다.

평가는 최종 정답·도구 선택·근거 Recall·불필요한 호출·예산 초과·권한 위반을 나눈다. 같은 질문에서도 도구 경로가 달라질 수 있으므로 trace와 버전을 기록한다. 현재 종합 프로젝트는 고정 흐름이며 자율 에이전트 실행을 구현했다고 표시하지 않는다.

## 실습과 평가

세 종류의 질문에 고정 흐름과 에이전트가 필요한 이유를 각각 작성한다. 도구를 두 개 추가하는 설계라면 잘못된 선택·반복·기한 소진·비인가 요청을 테스트 시나리오로 만든다.

실제 Agentic RAG를 도입할 때는 현재의 검색·인용·권한 테스트를 그대로 유지하고 동적 호출 제어 테스트를 추가한다.
