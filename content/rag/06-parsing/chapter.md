# 06장. PDF·HTML·표·스캔 문서 파싱

## 학습 목표

- 원문 모양과 추출된 텍스트의 차이를 검사한다.
- OCR·표·레이아웃의 실패를 검색 오류와 구분한다.

## 문서가 열리는 것과 내용이 추출되는 것은 다르다

PDF는 화면 배치 정보와 글리프를 담을 수 있지만 논리적인 문단·표·읽기 순서가 항상 명확한 것은 아니다. 두 단 문서에서 줄을 단순 연결하면 서로 다른 문장이 섞일 수 있다. 추출 결과를 실제 페이지와 표본 비교해야 한다.

스캔 PDF는 문자 레이어 없이 이미지로만 되어 있을 수 있다. 텍스트 추출 결과가 비었다고 원문이 비어 있다고 판단하지 않는다. OCR 후보로 표시하고 언어·해상도·회전·인식 오류를 별도 처리한다. OCR 정확도와 이후 검색 품질은 서로 다른 평가 계층이다.

```python
from ragbook.parsers import pdf_pages
pages = pdf_pages('sample.pdf')
for page in pages:
    print(page['page'], page['needs_ocr'], page['text'][:80])
```

이 함수는 텍스트 레이어와 빈 페이지 표시만 구현한다. OCR을 실행하거나 표 셀과 좌표를 복원하는 구현이 아니다. 예제의 테스트는 직접 만든 텍스트 PDF와 빈 페이지를 읽어 두 경우를 구분한다.

## HTML의 내용과 주변 장식

메뉴·푸터·쿠키 안내·반복 탐색 링크가 본문보다 많이 추출되면 검색이 잡음에 끌릴 수 있다. 제목·본문·목록·코드·표를 구분하고 script/style 내용은 제외한다. 단순 태그 제거 정규식은 중첩·엔티티·레이아웃을 올바르게 처리하지 못할 수 있다.

예제 HTMLParser는 블록 구분과 표 셀의 탭을 유지하는 작은 구현이다. 주제 본문 추출·복잡한 rowspan/colspan 복원·동적 렌더링은 하지 않는다. 페이지별 파서 전략을 선택하고 원문과 추출 결과를 비교한다.

## 표와 수치를 문장으로 잃지 않기

행·열 제목·단위·주석을 보존한다. 값 15가 휴가 일수인지 비용인지 열 제목을 잃으면 알 수 없다. 작은 표는 머리글을 반복해 행별 텍스트로 만들 수 있지만 교차 셀·병합 셀이 많으면 구조화 표현이나 원본 이미지 검색이 필요할 수 있다.

변환한 설명이 원본 수치를 바꾸지 않았는지 검사한다. 모델로 표를 요약할 때도 생성된 설명은 새로운 파생 자료이며 원본을 대체하는 사실 원장으로 취급하지 않는다.

## 파싱 품질을 별도 기록

빈 텍스트 비율·깨진 문자·반복 머리말·표 누락·페이지 연결을 점검한다. 제한된 페이지·파일 크기·암호화 파일 정책과 실패 재처리를 둔다. 실패 문서를 조용히 제외하면 데이터 누락이 검색 품질 문제처럼 보인다. 파싱 실패 목록과 색인 수를 함께 관찰한다.

## 실습과 평가

tests/test_api_parsers.py의 PDF 테스트는 두 페이지를 생성하고 첫 페이지 텍스트·둘째 빈 페이지·페이지 수 상한을 확인한다. OCR은 미실행이다.

HTML 테스트에서 script 내용이 빠지고 A와 B 셀 사이 탭이 남는지 확인한다. 실제 운영 문서에는 PDF 화면과 추출 텍스트의 사람이 확인한 표본 기록도 추가해야 한다.
