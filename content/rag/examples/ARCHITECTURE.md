# 구현 범위와 데이터 경계

## 실제 구현

- 표준 라이브러리 BM25·정확 벡터 검색·RRF·MMR. 기본 문자 벡터는 신경망 의미 임베딩이 아니다.
- 선택형 FastEmbed 다국어 ONNX embedding, 다국어 cross-encoder, 로컬 Ollama JSON 생성.
- SQLite의 문서·청크·벡터·모델 signature, 원자적 문서 교체·tenant별 삭제.
- 검색 전 tenant/roles 필터, 리랭커·생성에 허용 근거만 전달, 반환 전 현재 청크 ID 재검사.
- 출처 멤버십·정확 부분 문자열·타입·길이 검사. 의미적 주장 지지는 별도 평가 대상이다.
- 기본 발췌 생성·근거 부족/모델 거절/인용 오류/근거 변경의 응답 구분.
- FastAPI 검색·질문·관리 API, 검증 후 완성 답변 SSE, 단순 화면.
- HTML 텍스트·PDF 텍스트 레이어 추출과 OCR 필요 신호. 실제 OCR은 구현하지 않았다.
- 문서 단위 P@k·Recall@k·RR·nDCG·거절 비교, 합성 dev/test 데이터.
- LangChain·LlamaIndex 검색 어댑터. 프레임워크의 외부 생성·tracing은 자동 활성화하지 않는다.

## 의도적으로 구분하는 보장

LLM quote가 원문에 존재해도 주장이 틀릴 수 있다. 테스트에 이 한계를 명시했다. 기본 lexical 겹침 거절은 보수적 데모이며 answerability 확률이 아니다. 의미가 맞지만 단어가 겹치지 않는 질문을 과도하게 거절할 수 있다.

생성 후 근거 재검사는 검사 시점의 삭제·권한 변경을 차단한다. 분산 시스템의 모든 순간에 원자적 권한 회수를 보장한 프로토콜은 아니다. 문서별 쓰기는 원자적이지만 여러 문서의 일괄 색인 전체는 하나의 트랜잭션이 아니다.

embedding 캐시의 ONNX/토크나이저 파일 해시를 signature에 포함한다. 캐시 경로에는 해당 모델만 둔다. 이름이 같은 모델의 파일 변경과 혼합도 새 인덱스 대상으로 본다. 모델과 패키지의 실제 결과는 검증 기록을 확인한다.

## 규모·운영 확장

검색은 허용 청크를 읽어 정확 순회한다. BM25도 설명용 통계 계산이며 대규모 역색인 엔진이 아니다. SQLite 단일 호스트와 CPU 모델 구성으로 다중 사용자 처리량을 인증하지 않는다.

운영 인증 제공자·TLS·ASGI/프록시 요청 바이트 제한·공유 요청 제한·전역 작업 예산·백업 복원·모델 스케줄링·배포 종료·분산 색인과 캐시는 별도 설계 대상이다. Pydantic의 문자열 길이 제한은 네트워크 본문 수신 상한을 대신하지 않는다.

## 본문 설명과 별도 실습 범위

HyDE·LLM 다중 질의·parent-child·다중 소스/SQL 라우팅·자동 Multi-hop·대화 메모리·Agentic RAG·전체 GraphRAG·멀티모달 추론·파인튜닝·LLM-as-judge는 개념·설계·평가 계획으로 설명한다. 모두 기본 서버에 구현·검증된 기능이라는 뜻이 아니다. pgvector ANN·OCR·클라우드 배포·전체 사람 검수도 별도 확인이 필요하다.

작은 synthetic fixture의 좋은 점수는 실제 고객·언어·산업 데이터에 대한 일반화 근거가 아니다. 실제 수행 결과와 미검증 범위를 검증 문서에서 구분한다.
